## Public HTML and SEO maintenance

The build renders public content and localized metadata before JavaScript. Only public Homepage, Site Settings, Forms and offer data is serialized into HTML; drafts, accounts, contacts entered by customers, access tokens and tracking secrets are excluded. Lazy account/dashboard chunks remain separate from the home entry.

Home metadata uses delivered Site Settings defaults when available. Service/collection/detail/contact templates own their route metadata. Canonical, social URLs and reciprocal language links require `VITE_SITE_ORIGIN`. Organization/service JSON-LD uses visible names/descriptions and configured identity/contact information; price-free wholesale inquiries do not claim retail Offer markup. Placeholder information pages and private/form/account routes remain noindex. Filtered catalog variants and missing offers are deliberately non-indexable.

Review/unconfigured builds remain non-indexable and do not emit a dummy sitemap. A configured live B2B build can generate sitemap entries from its rendered indexable public routes. Real API/site origins, client publication approval, regeneration after content/catalog edits, and hosting redirects/HTTP 404 behavior must be verified before launch. A static snapshot without an agreed refresh process is not final catalog freshness acceptance.

Current review bundle baseline: B2B entry approximately 359 kB / 114 kB gzip; wholesale approximately 12 kB / 4.6 kB gzip; inquiry receipt/tracking/history chunk approximately 16 kB / 5.8 kB gzip; account chunk approximately 26 kB / 8.1 kB gzip. Local measurements are development evidence, not field Core Web Vitals or ranking guarantees. No new FAQ, CMS, analytics account or speculative AI-search file was introduced.

The owner-approved motion uses `shared/assets/js/page-motion.js` in the public shell and `shared/assets/css/motion.css`. After feedback that reveals finished before the owner reached them, sections now begin about 18% inside the viewport, capped at a 160-pixel inset. They use a 720ms fade/20-pixel rise with a gentler easing and an 80ms stagger capped at 240ms. The wholesale image/copy and embedded form groups reveal independently instead of animating a tall parent once. Home copy uses the same 720ms pacing; hero images use 800ms. Their entrances start after the existing 220ms logo fade. Button, menu, feedback and gallery timings remain independent.

The observer supports lazy routes and arriving API content, avoids nested animations, reveals/cancels on focus or pointer input and cleans up pending/active motion on navigation. Only JavaScript registers the pending-reveal attribute, so content remains visible without JavaScript or browser animation support. Reduced motion shows pending content immediately. No animation dependency was added, and CURRENT Figma composition is preserved. CSS timing values are converted correctly whether the optimized build stores milliseconds or seconds. The same motion language applies as remaining public pages are built.

Verification: 46 focused page-motion cases pass across Chromium/WebKit, both languages and desktop/tablet/mobile home views, with representative Phase 2 routes, dynamic content, interaction cancellation, reduced-motion changes, cleanup and pre-rendered HTML without JavaScript. Existing logo/menu and gallery motion suites pass 14 and 18 cases respectively; 35 Node tests and both lint/review builds pass. Evidence: `output/playwright/phase-2-page-motion/results.json` and its screenshots.
